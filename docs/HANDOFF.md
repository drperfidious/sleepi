## Outcome and validation boundary

There is now a Swift 6 codebase, a generated Xcode project with four native targets, and a working Mac preview of the shared iPhone interface. The revised architecture preserves Apple's sleep records and alarm. The original refs were read and left intact; `refs/05-validation-and-decisions.md` records the findings that were confirmed, narrowed or rejected.

**This is not a signed or device-validated iPhone/Watch build.** The host has Swift 6.2.1 and Command Line Tools (Mac SDK), but no Xcode/iOS/watchOS SDKs. No installation, overnight sensing, background mic recording, real-device Health read, Watch transfer, or real haptic is being claimed. No personal health data or microphone recording was accessed during this work.

The code for Watch motion and gentle wake is gated behind `SLEEPI_DEVICE_PILOT`, which is absent from all generated configurations. The passive app and phone-audio implementation can be reviewed independently. All original three-night acceptance gates remain unpassed.

## Highest-priority next work

1. **Build all four destinations with Xcode.** Select a team and resolve any SDK-specific Swift 6 isolation, WatchKit, WidgetKit/control, AppIntent extraction or asset-catalog issues. Install on a paired iPhone / Series 8 and test both warm and cold starts. In particular, verify single-target Watch embedding with the exact Xcode version; this host can validate project structure but not installability. Don't change generated embedding paths based solely on an unrelated issue report.
2. **Validate Health sample provenance and time windows with real records.** Current source filtering requires Apple's bundle prefix plus `Watch` product type. Excluded samples produce unavailable data, not fabricated sleep. Review Apple source variants, sparse quantity samples and quantities whose `startDate` precedes detected sleep. A fresh bounded snapshot replaces earlier records after edits/deletions. Measure 91-day fetch/build cost under observer delivery and confirm timeout/completion behavior.
3. **Exercise the microphone lifecycle with a locked iPhone.** Permission denial/revocation, calls, Siri, native alarms, Bluetooth changes, media-service reset, low storage, process termination, library-save failure, playback completion and long sessions. Interruptions deliberately stop rather than silently auto-resume. Classifier gate thresholds are provisional. Verify event/clip alignment, inferred labels, raw-memory bounds, encoding size, thermal behavior and status honesty.
4. **Run the Watch protocol without a debugger.** Capture may have gaps; timers or scheduling can fail; no real-time sleep-stage or continuous-HR promise is made. Confirm relaunch delegate delivery, deadline fallback, repeat-haptic dismissal, phone-offline transfer, transfer retries, empty exports and data retention. The recorder lacks a stop mechanism in this implementation; ending a marker does not end the already-requested system capture.
5. **Audit persistence/erasure across both devices.** The iPhone deletes its own library; Watch pilot state and Core Motion's system recording are separate. Confirm behavior of queued pre-deletion Watch transfers, failed file transfers, missing clips and interrupted writes. Current paired-file transfer handling is deliberately small; durable retry/acknowledgment needs device validation before relying on it overnight.
6. **Validate accessibility on the real devices.** Large Dynamic Type, VoiceOver, reduced motion, small Watch case sizes, Lock Screen privacy and large translated text were not tested here. The Mac layout check does not certify iPhone/Watch accessibility.

## Deliberate limitations to preserve or improve explicitly

- No Health corrections, source-priority manipulation, gap-fill writing or hidden writer. “Write nothing” is the enforceable invariant.
- No claim that wake proposals improve accuracy. The current rule uses motion plus sparse nearby HR, shows feedback cards and never changes Apple's total. It does not yet draw a separate candidate lane on the hypnogram, use a trained model, or personalize thresholds.
- No true SRI, recovery score, continuous snore minutes, calibrated noise SPL, speaker attribution or clinical advice. Schedule variation, observed target shortfall and raw vitals have explicit names/coverage.
- Calendar-noon buckets can combine naps and fragmented bouts. The displayed “first/last sleep” is literal; it is not a validated main-sleep-session detector. Historical clock comparisons currently use the current timezone. Audit shift work and travel before broadening claims.
- The sound player supports start/stop and completion callbacks; its real-device audio-session behavior needs validation. Saved audio expires during subsequent app cleanup, not on an exact wall-clock background deadline.
- A Live Activity is a session marker, not proof that the mic is still running. The text reflects that. It may disappear before a long night ends.
- Control Center and Shortcuts use shared `OpenIntent`, not a custom-scheme `OpenURLIntent`. Normal widget taps still use `widgetURL`. Verify cold-launch routing while onboarding is incomplete.
- Widgets currently open Tonight. Health summaries / elapsed-time complications, RelevanceKit, Focus filters and automatic motion export are deferred.
- All local metadata and audio are excluded from backups. iOS files use protection until first authentication so new clips can be saved while locked. This is a conscious protection/recording tradeoff, not full locked-file inaccessibility.
- The app is for personal development. App Store privacy policy, submission validation and distribution are not done. TestFlight is not treated as an exemption from Apple's review requirements.

## Reproduce

```sh
./scripts/test.sh
./scripts/preview.sh
./scripts/generate_project.sh  # only after editing project.yml; requires XcodeGen
```

Destination build commands are in `README.md`. The test script handles the Command Line Tools installation's missing Swift Testing Foundation overlay without changing system files. The project has no third-party app dependencies. XcodeGen was downloaded from its official GitHub release into ignored `.build/tools`, not installed globally.

The repository was initialized locally because the starting directory was not a Git checkout. Nothing was published, uploaded, committed, or dispatched to another assistant. The user will pass this project to Fable for the requested audit/review/improvement.
